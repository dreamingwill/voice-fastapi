# 语音指令识别优化设计方案 (acc-opt)

## 1. 目标
针对 OrangePi 设备端，在复杂环境下实现高精度的指令识别（约50条核心指令），同时保留非指令语音的转录功能。采用纯规则方案，避免模型推理带来的计算开销。

## 2. 核心架构：两阶段处理

### 阶段 1：指令意图识别 (Intent Classification)
判断转录文本是否属于“指令”。

**判定规则：**
1.  **长度过滤**：指令文本通常在 2 到 30 个字符之间。
2.  **关键词触发**：包含核心关键词（如：检查、准备、停、起飞、点火、发射、各号、注意）。
3.  **正则模式**：匹配预定义的指令模版。

### 阶段 2：指令精确匹配 (Command Matching)
将确定为指令的文本映射到标准指令集。

**匹配策略：**
1.  **规范化 (Normalization)**：利用 `command_text_aliases.json` 进行错别字替换。
2.  **模版匹配 (Template Matching)**：
    *   模版结构：`[前缀] + [任务名] + [阶段]`
    *   例如：`(各号注意，)?(站综合信息检查)(五分钟准备|一分钟准备|停)?`
3.  **核心关键词提取**：如果模版未完全匹配，提取“任务”和“阶段”关键词进行组合匹配。
4.  **模糊兜底 (Fuzzy Fallback)**：仅在意图识别通过的前提下，使用 RapidFuzz 配合高阈值进行最后尝试。

---

## 3. 指令模式分解 (基于 zhiling.txt)

### 3.1 核心要素提取
*   **前缀 (Prefix)**: `各号注意[，]?`
*   **任务 (Task)**:
    *   站综合信息检查
    *   起飞信号检查
    *   第一次综合检查
    *   第二次综合检查
    *   模拟信息检查
    *   模飞检查
    *   对塔无线检查
    *   基地程序
    *   各号自跟踪检查/复查
    *   起飞 / 点火 / 发射 / 分机参数下发
*   **阶段 (Stage)**:
    *   五分钟准备
    *   一分钟准备
    *   停

---

## 4. 关键技术细节

### 4.1 意图识别器实现
在 `app/services/commands.py` 中引入 `IntentClassifier`，使用关键词字典和正则表达式进行快速判定。

### 4.2 多阶段匹配引擎
在 `CommandService` 中实现阶梯式匹配：
1.  **Exact Match**: 原始或规范化后直接等于库中指令。
2.  **Regex Match**: 基于 `Template` 的正则提取。
3.  **Keyword Combination**: 将识别出的 `Task` 和 `Stage` 拼接，再次尝试 Exact Match。
4.  **Fuzzy Match**: 仅作为最后的低频手段。
