# 语音指令识别准确性优化调研报告

## 1. 当前系统分析

### 1.1 现有架构

音频输入 -> VAD语音活动检测 -> ASR语音识别 -> 命令匹配 -> 外部转发
                +-> 音频增强(降噪/去混响)
                +-> 说话人识别

### 1.2 命令匹配机制

当前实现位置: app/services/commands.py

匹配流程:
1. 接收ASR转录的文本
2. 应用文本规范化(别名映射、字符归一化)
3. 使用 BM25 + RapidFuzz 混合算法:
   - BM25基于jieba分词进行初步检索
   - RapidFuzz进行模糊匹配(token_set_ratio)
   - 可选拼音匹配支持(权重0.4)
   - 数字处理(序号/数字一致性检查)
4. 阈值过滤(默认0.75)

关键参数:
- DEFAULT_MATCH_THRESHOLD: 0.75
- PHONETIC_WEIGHT: 0.4
- PHONETIC_THRESHOLD: 0.68
- NUMERIC_MISMATCH_PENALTY: 0.4

### 1.3 ASR引擎配置

当前模型: Sherpa ONNX Sense Voice (离线)
- 模型: sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09
- 支持多语言: 中文、英文、日文、韩文、粤语
- 语言: auto
- 解码方法: greedy_search

音频配置:
- 采样率: 16000Hz
- VAD参数: pre_roll=300ms, post_roll=200ms
- 最小说话时长: 1.5秒

### 1.4 音频增强模块

位置: app/services/audio_enhancement/

- 降噪: 频谱减法(经典/改进)
- 去混响: WPE算法
- 通过WebSocket握手配置

## 2. 问题分析

### 2.1 识别准确性限制因素

| 因素 | 影响 | 当前状态 |
|-----|-----|---------|
| 设备计算能力 | 限制模型复杂度和处理速度 | OrangePi，NPU推理 |
| 麦克风质量 | 影响信噪比(SNR) | 设备端未知 |
| 环境噪声 | 导致ASR错误率上升 | 通过VAD和降噪缓解 |
| ASR转录错误 | 基础文本不准确 | Sense Voice，离线模型 |
| 误匹配风险 | 非指令文本被匹配为指令 | 无指令/非指令分类 |

### 2.2 当前匹配算法的局限性

1. 无指令意图分类: 所有转录文本都尝试匹配，容易产生误报
2. 纯文本相似度: 忽略语义特征，仅基于字符/拼音/分词
3. 固定阈值: 无法动态调整匹配严格度
4. 无上下文感知: 不考虑历史对话状态

### 2.3 客户建议的合理性

"将文本匹配做成一个分类任务，先判断是否为指令，再进行匹配"

优势:
- 减少误报: 对话/闲聊不会被错误匹配
- 提高置信度: 只对指令意图明确的文本进行匹配
- 可调节性: 分类阈值和匹配阈值可分别优化

## 3. 优化方案设计

### 3.1 核心方案: 两阶段分类+匹配架构

ASR转录文本
    +-> [阶段1] 指令意图分类
    |   |-- 是指令(概率 > T1) -> [阶段2] 命令精确匹配
    |   |-- 非指令(概率 <= T1) -> 返回转录结果，不进行匹配

#### 3.1.1 阶段1: 指令意图分类器

目标: 判断一段语音转录是否包含指令意图

技术选型 (按推荐优先级):

| 方案 | 优势 | 劣势 | 适用场景 |
|-----|------|------|---------|
| 基于规则的意图识别 | 无需训练，可解释性强，轻量级 | 需手工编写规则，泛化能力有限 | 指令模式固定，可预定义 |
| 轻量级文本分类模型 | 自动学习特征，可扩展 | 需要训练数据，增加计算开销 | 指令模式多样，需要学习 |
| 基于Embedding的相似度 | 语义理解能力强，无需训练分类器 | 需要计算向量相似度 | 现有embedding基础设施 |

推荐方案: 基于规则的意图识别 + 可选的轻量级分类器

规则设计思路:
1. 关键词特征: 打开、关闭、切换、设置、查询、开始、停止、播放等
2. 句式结构特征: 疑问句、祈使句识别
3. 长度过滤: 通常指令较短，超过50字符可能是对话
4. 标点符号: 疑问号结尾
5. 可选轻量级分类器用于增强

#### 3.1.2 阶段2: 增强的命令精确匹配

优化现有BM25+RapidFuzz方案:

1. 添加语义相似度: 如果有embedding，可结合余弦相似度
2. 动态阈值: 根据分类置信度调整匹配阈值
3. 重排序机制: 使用更复杂的排序策略

动态阈值示例:
- 根据分类置信度动态调整阈值
- 高置信度指令使用稍低阈值
- 低置信度指令使用更高阈值

### 3.2 辅助优化策略

#### 3.2.1 ASR转录后处理

ASR纠错:
- 拼音相似字纠正
- 常见错误模式替换
- 可选: 语言模型重评分

多候选处理:
- 利用ASR输出的N-best结果
- 对每个候选进行意图分类和匹配
- 综合得分选择最佳结果

#### 3.2.2 上下文感知

对话状态跟踪:
- 跟踪历史命令和非指令计数
- 连续非指令: 降低阈值避免漏检
- 连续指令: 提高阈值避免误报

#### 3.2.3 自适应阈值

基于用户反馈的阈值优化:
- 记录用户的匹配确认/修正
- 动态调整个人阈值
- 收集统计指标: 精确率、召回率

### 3.3 长期优化方向

1. 端到端指令识别模型:
   - 直接从音频到指令代码
   - 需要大量标注数据

2. 主动学习:
   - 收集边界案例进行标注
   - 持续改进分类器和匹配器

3. 模型蒸馏:
   - 将大模型蒸馏到小模型
   - 适应OrangePi的计算能力

## 5. 评估指标

### 5.1 命令识别指标

| 指标 | 定义 | 目标 |
|-----|------|-----|
| 精确率 (Precision) | 匹配的命令中正确的比例 | >= 95% |
| 召回率 (Recall) | 实际命令中被正确识别的比例 | >= 90% |
| F1分数 | 精确率和召回率的调和平均 | >= 92.5% |
| 误报率 | 非指令被匹配为指令的比例 | <= 5% |
| 漏检率 | 指令未被识别的比例 | <= 10% |

### 5.2 分类器指标

| 指标 | 定义 | 目标 |
|-----|------|-----|
| 指令识别准确率 | 正确判断是否为指令的比例 | >= 95% |
| 指令召回率 | 指令被正确识别的比例 | >= 95% |

### 5.3 端到端指标

- 50条指令识别准确率: >= 98%
- 非指令转录成功率: >= 99%

## 6. 风险与挑战

| 风险 | 影响 | 缓解措施 |
|-----|------|---------|
| 规则覆盖不全 | 新指令模式无法识别 | 持续收集反馈，扩展规则 |
| 误报控制困难 | 非指令被错误匹配 | 调整分类阈值，加强上下文感知 |
| 计算开销增加 | 影响实时性能 | 优化算法，使用轻量级模型 |
| 领域迁移困难 | 新场景需要重新适配 | 设计可配置的规则和参数 |

## 7. 配置参数建议

command_matching配置新增:
- intent_classifier: 指令意图分类器配置
  - enabled: 是否启用
  - type: rule_based 或 ml_based
  - threshold: 分类阈值
  - rules_file: 规则文件路径

- dynamic_threshold: 动态阈值配置
  - enabled: 是否启用
  - min_threshold: 最小阈值
  - max_threshold: 最大阈值
  - confidence_weight: 置信度权重

- context_aware: 上下文感知配置
  - enabled: 是否启用
  - command_history_window: 命令历史窗口
  - non_command_reset_count: 非指令重置计数
